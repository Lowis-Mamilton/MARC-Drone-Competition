# MARC 火線救援無人機模擬器

依本資料夾的 2027 賽季「程式控制組」與「遙控＋程式組」規則製作的獨立教學模擬器。沿用 Football Drone Simulator 的 Godot 四馬達物理、手機控制與手把校正，新增比賽場地、定位懸停、Scratch 積木、感測與競賽判定。

## 目前測試入口

內建編程版請開啟 .runtime/studio/MARCDroneStudio.exe，或執行 npm.cmd start。同一視窗左側編排無人機積木、右側顯示場地；工具箱不顯示貓咪、角色、造型、音效等設定。啟動自帶起降範例，另有前進返航及 LED 變色範例，詳見 [無人機積木入門](docs/DRONE_PROGRAMMING.md)。目前先供測試，以下舊可攜版尚未更新成此介面，待測試通過後再打包。

## 啟動

Windows 10／11 x64：解壓縮完整可攜版，開啟 `MARCDroneSimulator.exe`。`MARCDroneSimulator.pck`、`web` 與 `examples` 必須保留在 EXE 同一個資料夾。Scratch 使用本機 Edge 或 Chrome，執行時不需網路、帳號、Python 或 Node.js。手機控制需要同一個 Wi-Fi，並允許模擬器通過私人網路防火牆。

原始碼資料夾可執行 `start-simulator.ps1`；若已有 `dist` 版本會啟動該版本，否則以開發引擎啟動。

## 第一次試飛

1. 保持「自由練習」，選擇組別。先切換「俯視」確認場地位置。
2. 在「控制」頁按「起飛／降落」，或按 Space 起飛至底部離地 50 公分。
3. W/S 前後、A/D 左右、Q/E 轉向、R/F 升降；放開即定位懸停。Space 降落，Backspace 重置，Esc 緊急停機。
4. 使用「選手視角／跟隨／FPV／俯視」切換觀察；選手與跟隨視角可滑鼠拖曳旋轉、滾輪縮放。
5. 到「設定」可指定色卡、重新抽色及開啟練習飛行路徑。

Xbox／PS／標準 FPV USB 手把採 Mode 2：左桿定高速度與轉向，右桿前後與左右。A／Cross 起降、B／Circle 切換視角、Menu／Options 重置。搖桿居中代表維持高度；無回中油門的手把須將油門置於校正範圍中點才懸停。先降落，再使用「擷取中心」及「行程校正」，完成後儲存至本機。控制來源自動選擇順序為手機、手把、鍵盤；切換或斷線時安全降落。

手機可掃描「控制」頁 QR code。手機頁面的 Arm 按鈕在本模擬器對應起飛／降落；油門 50% 為維持高度，0% 為下降。原足球模擬器頁面的 Acro 切換在 MARC 模式不使用。

## Scratch 編程

在「Scratch」頁按「開啟 Scratch 編輯器」。本機地址為 `http://127.0.0.1:41830/scratch/?locale=zh-tw`；若連接埠被佔用，以模擬器開啟的地址為準。

編輯器使用官方 Scratch GUI／VM 15.2.0，MARC 擴充已自動載入。可使用原生條件、變數、重複、廣播及自訂函式。右上角可載入三個 `.sb3` 範例；先儲存自己的專案，再載入範例。

| 積木 | 行為 |
| --- | --- |
| 起飛至 H 公分 | 起飛並等待高度穩定 |
| 飛至 x、y、高度 | 使用場地絕對座標定位 |
| 沿場地移動 x、y、高度 | 沿固定場地軸相對移動，不隨機頭旋轉 |
| 逆時針轉向 D 度 | 原地轉向；負數為順時針 |
| 降落 | 垂直下降至接觸地面，關閉馬達 |
| 懸停 S 秒 | 保持定位，等待指定秒數 |
| 底部感測顏色 | 回傳 `red`、`yellow`、`green`、`blue` 或 `none` |
| 設定 LED／同步底部感測顏色 | 更新燈號；同步後仍須懸停至少兩秒 |
| 無人機座標／高度／航向／速度 | 讀取即時遙測 |
| 停止飛行程式 | 取消待執行飛行並懸停 |
| 結束比賽 | 須先降落並完全靜止 0.5 秒 |

所有距離為公分，**高度是無人機底部距地面**。機身碰撞包絡半徑 10 公分，所以穿越圓心離地 100 公分的捷徑時，積木目標高度設為 **90 公分**。航向 0 度朝 x 正方向，90 度朝 y 正方向。

綠旗先取得程式控制權，再依積木執行；每個飛行積木等待位置誤差小於 3 公分、航向誤差小於 5 度且穩定 0.3 秒。多條腳本的飛行指令依接收順序執行，感測積木可隨時讀取。飛行動作超過 30 秒未完成時停止程式並提示；等待積木依設定秒數計時。

紅色停止鈕取消指令並懸停；Esc 或模擬器「緊急停機」立即關閉馬達。Scratch 斷線或三秒未收到心跳時，取消指令並降落。正式比賽計時持續。

「檔案 → 儲存到你的電腦」可下載 `.sb3`，再透過「從你的電腦挑選」重開。MARC 自訂積木須使用本專用編輯器執行，Scratch 官網未安裝此擴充。

## 比賽模式

| 組別 | 流程 | 計分 |
| --- | --- | --- |
| 程式控制組 | 準備 60 秒 → 自主飛行 180 秒 | 起飛 10、① 40、② 20、③ 20、④ 50、⑤ 20、⑥ 20、⑦ 90、⑧ 30；滿分 300 |
| 遙控＋程式組 | 檢查 30 秒 → 遙控 90 秒 → 交接 30 秒 → 自主飛行 150 秒 | 第一階段 100、第二階段 100；滿分 200 |

「開始比賽」會重置場地並抽取色卡；準備期間可按「裁判口令：開始」提早結束準備。遙控組第一階段任務按 ①A、①B、②、③、④A、④B、④C、⑤ 順序進行；跳過不能補分。交接時自動放回停機坪中央。自主階段封鎖鍵盤、手機與手把飛行控制，只允許 Scratch 啟停、緊急停止和合法重置。

程式組及混合組第二階段可重置，計時不中斷；保留分數、次數上限及色卡首次判定，色卡不重抽，道具歸位。第一階段不能重置，可由裁判宣告故障進入交接。

穿圈須整個機身按指定方向通過；標杆須在杆頂以下完整逆時針環繞；斷橋須先由 E 側完整下穿至 D 側，再從上方返回 E 側。程式組隧道連續加分只在 A→B→C 之間沒有其他得分任務時成立。

色卡以底部感測點位於卡內、距卡面 30 公分內判定；LED 連續同色至少兩秒才作首次判定。白色與關閉不作答，首次答錯鎖定該卡直到下一場。最後降落分於結束時結算；重新起飛或移動會撤銷暫定分數。

「裁判」頁可登錄人員接觸、擅自進場、未依程序介入、重大違規等無法由模擬位置自動辨識的事件。自動計分紀錄與人工裁判事件一併保存。「紀錄」保存每組最近三場，顯示最高分並可匯出 JSON；沒有多人隊伍排行榜。

## 場地資料與判定約定

- `config/course.json` 集中規則座標、格距、限高、道具尺寸與建議高度。修改後重新啟動；可攜版內的 PCK 已包含設定，修改原始碼設定後須重新打包。
- 以 A0 左下角為原點，x 朝 9 欄、y 朝 H 列，Godot 對應 `(x/100, 高度/100, -y/100)`。停機坪中心 `(40,160)`，機頭朝 x 正方向。
- 正式機型與公告高度未定，預設使用直徑 20 公分的球形碰撞包絡、教學四軸外觀及既有通用馬達物理。這不是特定機型的硬體驗證或韌體模擬。
- 圈徑按有效內徑解讀；地面圈線寬預設 1 公分。最後降落以機身圓形投影判斷：完全位於內圈且不碰線 30 分；中心在內圈且機身碰線 10 分；其餘 0 分。
- 障礙碰撞可使支架傾倒；單純擦碰不自動扣碰倒分。道具倒下後不能繼續計該道具，須合法重置歸位。
- 混合組的「嘗試後跳過」以穿越圈面、開始下穿斷橋、完成標杆環繞或色卡兩秒作答等可觀測事件判定；需要裁判主觀認定的行為由裁判操作記錄。每個非本階段道具的任務違規扣分每階段至多登錄一次。
- 場地邊界與限高採警示，裁判可要求重置，不使用隱形牆。

比賽紀錄與手把校正預設保存於 Windows 使用者的 Godot 應用程式資料夾，與足球模擬器分開。開發測試透過 `run-godot.mjs` 將資料隔離至 `.runtime/roaming`。

## 開發與驗證

需要 Node.js 22+、Godot 4.7.2 Standard 與相符的 Windows x64 匯出模板。

```powershell
cd scratch
npm.cmd ci
cd ..
npm.cmd run build:scratch
npm.cmd run examples
$env:GODOT_PATH = 'C:\path\to\Godot.exe'
node scripts/run-godot.mjs --headless --editor --import --quit
npm.cmd test
node scripts/run-godot.mjs --headless --script res://tests/godot/test_runner.gd
node scripts/run-godot.mjs --headless --script res://tests/godot/flight_test.gd
```

啟動開發版：`node scripts/run-godot.mjs`。Scratch 瀏覽器測試需先啟動模擬器，再執行 `node scripts/browser-test.mjs`；預設地址 `41830`，可設定 `MARC_URL` 改用其他地址。視覺預覽：`node scripts/run-godot.mjs --script res://tests/godot/ui_preview.gd`。

Windows 打包：`scripts/build-windows.ps1 -GodotPath C:\path\to\Godot.exe -TemplatePath C:\path\to\windows_release_x86_64.exe`。輸出到 `dist`，包含本機 Scratch 編輯器與範例。保留 `scratch/package-lock.json` 以重建相同依賴。

打包後執行 `node scripts/release-smoke.mjs` 驗證 EXE 與 Scratch，再以 `python scripts/package.py` 製作可攜版及原始碼 ZIP。測試結果與適用範圍見 [驗證紀錄](docs/VALIDATION.md)。

手機與遙控器設定已整合至工作室上方「手機遙控／遙控器設定」；操作與校正流程見 [遙控器說明](docs/CONTROLLERS.md)。支援 Mode 1／Mode 2、自訂映射、反向、死區、靈敏度、即時監看、校正與設定匯入匯出。
